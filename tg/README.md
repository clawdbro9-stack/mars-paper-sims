# Telegram forward paper experiment
Standalone local stdlib Python daemon. Never wallets, keys, real orders, AI calls, chat sends or external post links. Baselines public preview IDs on first successful read; only newly seen, <=120-second-old posts considered. Explicit Solana/SOL + single base58 mint + entry intent must occur in SAME post; adjacent contract-only posts and tickers deliberately skipped. Public preview may omit messages; gap logged, no backfilled trades.

Public sources:
- https://t.me/s/cryptotalkwithfrog
- https://docs.dexscreener.com/api/reference (GET token-pairs/v1/solana/{mint})
- https://docs.gopluslabs.io/reference/solanatokensecurityusingget (GET api/v1/solana/token_security?contract_addresses={mint}, no auth used)

Rules in rules.json are EXPERIMENTAL, not a proven edge. $25 separate cash; each $6 debit INCLUDES estimated entry costs, max 3 open positions, never debit below $7 reserve. No leverage, all-in, trade quota, or time-based exit. No global loss cutoff specified. Per-coin cumulative committed tracked forever; adds disabled (no holder/flow history), even though hypothetical add gate ceiling tested at $9.

Safety: exact mint market match; liquidity >=$100k; 24h volume >=$10k; all checked mint/freeze/balance-change/close/default-state-change/fee-change/hook-change authorities disabled; initialized transferable account; no hooks, no transfer fees; top holder <=10%, top10 sum <=40% including tagged addresses conservatively. Missing fields fail closed. GoPlus risk snapshots do NOT guarantee future sellability, detect every scam, or independently simulate sells. No executable swap quotation; paper estimated fills only. DexScreener has no quote timestamp: request-time freshness only, not proof quote is live. Known illiquidity, safety failures or missing feeds block fills and log failed-sell risk, retaining exposure. Marks may be stale during gaps and are not executable equity. Slippage may far exceed assumptions or asset become unsellable.

Cost model: fee 0.3% plus adverse slippage 1% each side, gas $0.01 per fill; fixed USD estimate not measured SOL gas. Debit $6 including entry costs. Exit proceeds net of these assumptions; trades at observed prices, never phantom stop prices. Accounting allocates original total-cost basis pro rata units; status equity deducts estimated close costs.

Initial stop 50% below observed entry. [Nov 9 2026: former +30% cost-protection stop REMOVED — see below.] At +50% sell 1/3 original units and activate 20% peak trail. At 2x sell only additional units needed for TOTAL net proceeds to reach original $6 including costs; prior proceeds count. At 3x sell 20% ORIGINAL units capped by remaining. Significant runner is defined as remaining position AFTER recovery and 3x distribution; when its gross value reaches $6 sell HALF remaining ONCE, trail rest. This interpretation avoids treating an initial $6 position as already a significant moonbag. Stops only tighten; price jumps execute crossed tiers sequentially; partials never oversell. No 2h limit.

Poll preview 60s. Position monitor target 15s until recovered and age>=1h, then 60s; network calls can delay cadence (10s timeout each). Rechecks safety every position observation; max 3 positions so bounded calls. Health probe of FLOAT every 5min is DATA ONLY and never entered. Watcher heartbeat every ~5s when not waiting on requests.

Run: nohup python3 /workspace/mars-tg-paper/supervisor.py >> /workspace/mars-tg-paper/supervisor.log 2>&1 < /dev/null &
Stop: python3 /workspace/mars-tg-paper/stop.py
Tests: cd /workspace/mars-tg-paper && python3 -m unittest -v
Inspect status.json, state.json, events.jsonl and supervisor.log. Local events are the only alerts. Atomic state writes and locks prevent parallel instances; persist consumed ID before processing (at-most-once: crash can miss an entry, never intentionally backfill it). Supervisor restarts child crashes, NOT machine reboots or supervisor termination. State stays for manual supervisor restart. No system service/cron installed.

## Version 2 channel adaptation (Nov 7)
Supersedes same-post chain-word requirement above. Fresh call+mint can be in one post OR explicitly replied-to posts (<=120s) OR adjacent IDs <=30s, exactly one call and one bare-mint companion. Competing nearby calls or multiple mints skip. Chain/identity validated through exact mint Solana DexScreener market plus GoPlus Solana metadata (call ticker must match metadata symbol when present). Never infer identity from ticker alone for buys. Pending context only contains newly observed posts, not old baseline; consumption/actions persisted, edits ignored. Call freshness max120s. Cross-poll split linking supported. Parser excludes quoted reply text; negated/conditional/recap/multiple claims are not entries. Unknown speech is observe/skip, never arbitrary instructions.

Explicit nonnegated channel profit/trim updates may sell HALF currently held units; explicit exit/close/sell-all updates may sell ALL. Requires exact mint OR unique held metadata ticker, fresh independent market and unchanged safety gates. Source IDs log provenance; posted price/cap/claims never supply price. Dedupe per action/source IDs. Automatic adds/reentries remain disabled, lifetime coin commitment unchanged. Goal dashboard $250 NET estimated equity target plus realized/unrealized, no deadline or promise.

Profit/stop settings unchanged. A multi-day hold may be cut by 20% trail; widening is not justified from one selected winner or available preview. No already-active stop widened. Still no measured flow/holder-dump history, volatility-calibrated runner model, guaranteed fills, or global loss rule.

## Version 4 changes (Nov 9 2026)
**Removed the +30% cost-protection / break-even stop.** It was added by Mars and never approved by the Captain. It raised the stop to break-even after any +30% move and was the reason the SHIIT counterfactual was stopped out. Removed: `protect_at` from rules.json and the stop-raise block in `sim.manage()`. The Captain's actual rules: −50% initial stop; take smaller profits earlier ONLY when a trade clearly deteriorates (sell pressure, liquidity drain, failing safety gates), not automatically after any +30% move; sell most at 2–3x and hodl the rest for 10x; protect moonbags once significant; all-in never automatic; adds/leverage disabled. Unchanged: +50% sell 1/3 then 20% peak trail, 2x recover $6, 3x sell 20%, significant-runner half. The final stop check's log reason is now `trail_after_plus50` (was `tightened_cost_protection`). RULE_VERSION=4.

**Multi-level reply-chain identity.** Post 9805 ("SEND THIS $SHIIT NOW") replied to 9803, which replied to mint post 9793. V3 only read the immediate quote, so it was skipped. V4 changes:
- `signals.chain_identity` walks `reply_to` up to 5 hops using stored post context. When a parent isn't stored, it falls back to the child's embedded quote. Intermediate posts must carry no ticker or the same ticker. The mint-bearing ancestor must name the same $TICKER and contain exactly one mint or pair. Conflicts, multiple identities and cycles all skip.
- `signals.ticker_identity` is the fallback when there is no reply link and no adjacent CA companion. It looks up earlier stored posts (≤30 days) that name exactly that $TICKER with one mint. They must all agree on a single mint, or the call is skipped.
- "send this/send it" with a single $TICKER is now recognized as call language. Negations still block it.
- sim.py stores first-seen post context in `state.json` under `context` (last 400 posts, identity only, never replayed).

All of this is identity evidence only: the call post itself must still be fresh (≤120s) and forward-seen. Metadata symbol and safety gates are unchanged. Old posts, including the real 9805 (seen ~10.5h late), are not retro-traded. Ledger unchanged. Tests: test_reply_chain.py. Backup of v3 files: backup-v3-20261109/.
